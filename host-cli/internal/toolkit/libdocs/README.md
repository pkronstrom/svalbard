# Library quickstarts and reference files

One folder per `js-lib` recipe (`recipes/js/<id>.yaml`). Apply writes, for
each library in the recipe's `libraries:`, into `lib/js/<id>/docs/` on the
vault:

- `<name>.md`, the quickstart: frontmatter that apply generates from the
  recipe (package, version, licence, measured portability, entry,
  `requires: [<id>]`) followed by the file here. `<name>` is the package
  name with `/` as `__` (`@jscad/modeling` → `@jscad__modeling.md`).
- `<name>.reference.md`, the reference file: the project's own Markdown
  docs at the pinned version joined into one file, or its README and type
  definitions where it has none. Generated by `build-tools/cmd/js-docs`
  from the `docs` section of `recipes/js/<id>.lock.json`; do not edit it
  by hand.

The drive's `skill_search` finds a library by its quickstart, and
`skill_read` lists the reference file as the quickstart's file. This
README is not written to vaults.

## Quickstarts

Read by small local models with no network. Write for that reader:

- First the exact import line, then one complete page that packs as it is
  with `svalbard-drive html pack` and works when opened. Data files are
  imported (`import rows from "./data.csv"`), never fetched.
- Say what small models get wrong for this library (Three.js addons come
  from `three/addons/...`; p5 stays on 1.x with `preload()`; Mermaid is a
  classic script loaded with `<script src="mermaid">`).
- No version numbers in the text: the frontmatter carries the pinned one.
- End with what the reference file holds.

`make verify` runs the skills' offline check on every quickstart, and on
every reference file except the lines js-docs marked "Not for this drive:"
and blocks fenced `not-for-this-stick`. It also fails a catalog library
without both files, and checks each recipe's size budget
(`libdocs_catalog_test.go`).
