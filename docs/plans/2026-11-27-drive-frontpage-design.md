# Offline drive frontpage

The drive's existing `./run` launcher accepts `web` to open an offline dashboard on a private loopback port. The terminal menu also offers it on newly applied vaults. The dashboard uses the installed groups, descriptions and arguments from `.svalbard/actions.json`, so it can open individual ZIMs in Kiwix, list document collections, and start maps, Open WebUI, Wiki and bundled web apps. It shows terminal instructions alongside actions that require a terminal.

A persistent sidebar groups installed items by the same sections as the terminal menu. Its filter matches names and descriptions. The main pane shows the selected item, search results, or its reader. Kiwix, documents and local web apps can be opened in the pane or in a separate tab. Wiki and Open WebUI open in their own browser tabs. Indexed search uses the drive's existing read-only search session. The saved HTML gallery discovers pages within `workspace/`, including project subfolders. The existing confined workspace server serves pages on a separate origin and permits embedding by the local dashboard. The Wiki action opens the existing SilverBullet editor and preserves its Markdown storage.

Overview lists each installed action and saved HTML app with a short description. Its filters use the catalog's recipe tags and item types. It can group by type or show an alphabetical list. Selecting an item opens its details. **Serve & open** starts it directly. Optional recipe thumbnails are prepared during host apply and served from the drive. A bundled notebook illustration fills in for each type when the recipe has no usable image.

The dashboard starts one loopback Kiwix library on demand and adds archives as users open them from Overview, the sidebar, or search. **Serve Everything** can use that same library and keep the full collection loaded. Stopping an individual archive removes it when its last service releases it. Older vaults with only `kiwix-serve` use the standalone reader.

The Settings detail view includes a terminal with `./run settings` ready to submit. The terminal calls the runtime's existing settings command and displays its text output. It accepts the same list, read, set, reset, and help forms. Its command endpoint uses the dashboard's same-origin POST controls and accepts only settings arguments. The command transcript stays in the browser tab.

A managed action exposes its starting, running, stopped or failed state. The dashboard uses the running service's URL, deduplicates identical launches, and stops its services when it exits. Explicit local-network sharing uses the existing Share action. A loopback address, exact Host check, and same-origin POSTs constrain dashboard controls. Browser requests select a known action and, for Open WebUI, may select an installed model.

Verify the generated launcher and browser routes using a tiny vault with one cached archive, a test document and workspace pages. Exercise search and lifecycle behavior in tests and reuse the existing small launch fixtures for Open WebUI and Wiki.
