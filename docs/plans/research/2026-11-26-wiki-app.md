# Wiki app for the drive: LeafWiki vs SilverBullet

Date: 2026-11-26. Source: both repos read at their latest release tags (LeafWiki `v0.15.0`, SilverBullet
`3.0.1`) and the GitHub releases API. Nothing was run. Builds on
`docs/plans/research/2026-11-21-tool-candidates.md` §2, which predates SilverBullet 3.0.

**Headline:** SilverBullet 3.x is no longer a Deno server. It is a static Rust binary that watches its space
folder, so files changed on disk show up in the UI and in search without a restart. LeafWiki does not
watch, and in no-login mode a running server can only be told to resync by a Unix signal.

## Requirements

Runs from the stick on macOS (arm64, x86_64) and Linux (x86_64, arm64), with no internet, no Docker and no
install. Pages are plain Markdown files on disk, and local agents (pi, goose, Open WebUI over the svalbard
MCP server) must be able to read, create, edit and append pages.

## Comparison

| | LeafWiki v0.15.0 | SilverBullet 3.0.1 |
|---|---|---|
| Release | 2026-11-22 | 2026-11-26 (3.0.0 on 2026-11-24 was a major release with breaking changes) |
| Assets | `leafwiki-v0.15.0-{darwin,linux}-{amd64,arm64}`: plain binaries of 38–41 MB, each with a `.sha256` | `silverbullet-server-{darwin,linux}-{x86_64,aarch64}.zip`: zips of 17–20 MB |
| Binary | Go with `CGO_ENABLED=0`, pure-Go SQLite (`modernc.org/sqlite`) | Rust. Linux builds are static musl, and CI fails a dynamically linked build. Optional extras: system `git` for revisions, Chrome for the Runtime API |
| Pages | `.md` under `data/root/`. Folders form the tree, a section is `index.md`, sibling order is in `.order.json` | Plain `.md` in a space folder. The path is the page name |
| Sidecar state | `leafwiki_id`, title, timestamps and author fields written into each page's frontmatter, plus about 10 SQLite DBs (search, links, tags, users…) | `spaces.json`, `users.json`, `server.json`, and a tantivy index in `search/`, all in the data folder and kept apart from the pages |
| **External edits** | **Not watched** (no fsnotify in the source). Edits to an existing page show on the next read. New, moved or deleted files, search, links and tags all need a resync | **Watched** by the `notify` crate (`server/src/watcher.rs`). `SB_FS_WATCH=auto\|poll\|off`. Changes are pushed to open clients, and search updates about a second later |
| Resync | `SIGUSR1`/`SIGHUP`, or `POST /api/admin/resync`. That route is admin-only, and `RequireAdmin` returns 403 when `--disable-auth` is on (`internal/http/middleware/auth/auth.go:73`) | Not needed |
| Frontmatter rewrite | A resync writes a `leafwiki_id` into any file that lacks one, so files agents write change under them | None |
| HTTP API | Undocumented and labelled experimental. Pages are addressed by ID. Writes need a CSRF cookie and an `X-CSRF-Token` header even with auth disabled. API keys are "not yet ready" | Documented: `GET/PUT/DELETE /.fs/<path>.md` with ETag `If-Match`, and `POST /.search/query`. Bearer token, or no auth on an anonymous-writable space |
| MCP | None built in (feature request #1273 is open). Two community servers with 1–2 stars | Built in at `/.mcp`, but OAuth 2.1 only, off by default and labelled experimental |
| Auth and LAN | `--disable-auth`, or `--jwt-secret` and `--admin-password`. Plain HTTP also needs `--allow-insecure`. Binds `127.0.0.1` | `silverbullet setup <dir> --admin user:pass`, or no accounts with an anonymous-writable space. Access is per space (none, read or write). Binds `127.0.0.1`; `-L 0.0.0.0` for the LAN |
| Flags | `--host`, `--port`, `--data-dir` | `-L`, `-p`, folder as an argument. Set `SB_UPDATE_CHECK=0` to stop the daily update check |
| Search | SQLite FTS5; stale after external edits until a resync | tantivy with stemming, kept live by the watcher. Optional semantic search downloads a 220 MB model |
| exFAT | Not verified. SQLite runs in WAL mode, which needs a shared-memory file | Not verified. tantivy uses mmap and lock files |
| License, activity | MIT, 1,245 stars, 797 commits in 6 months, one main maintainer | MIT, 6,644 stars, 986 commits in 6 months, one main maintainer |

## Verdict

**SilverBullet 3.x.** It is the only candidate where agent-written files are first-class. It also offers a
path-addressed file API with conditional writes, runs with or without accounts, and is a smaller download.

- **Main risk, SilverBullet:** 3.0 is days old and changes a lot. Pin 3.0.x. Before shipping, test the
  watcher, tantivy and revisions on an exFAT stick under macOS and Linux; `SB_FS_WATCH=poll` is the
  fallback. Its object index (queries, backlinks) is built in the browser, so agents get server-side
  full-text search only.
- **Main risk, LeafWiki:** external files are second-class: no watcher, frontmatter rewrites, a resync
  that needs a signal, an experimental ID-addressed API with CSRF, and about 10 SQLite databases on the
  stick.
- **Others ruled out:** Otter Wiki (needs Python), Gollum (Ruby), TiddlyWiki (no plain Markdown files),
  Memos (SQLite storage), Flatnotes (Docker), Wiki.js, BookStack and Trilium (database storage).

Facts verified by hand against the clones: no fsnotify in LeafWiki, `RequireAdmin` returns 403 with auth
disabled, and SilverBullet's `notify` watcher with `SB_FS_WATCH`.
