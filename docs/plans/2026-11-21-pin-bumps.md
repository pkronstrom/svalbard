### Notes on specific bumps

- **7-Zip 26.06 splits the macOS build.** `7z2606-mac.tar.xz` is now arm64 only (checked with `lipo`). The new `7z2606-mac-x64.tar.xz` covers Intel. In 26.05 a single universal file served both, so `macos-x86_64` now points at `-mac-x64`.
- **llama.cpp v1.0.0 is a major milestone.** v-tags have no binaries. The release notes name nightly b12359 as the v1.0.0 build. That follows the pattern of v0.7.0 → b11669 and v0.9.0 → b12110.
  - Every flag svalbard passes appears in the b12359 macOS arm64 binaries. I checked with `strings`, without running the binaries. The flags are `--model/-m`, `--port`, `--host`, `--embedding`, `--ubatch-size`, `--batch-size`, `--ctx-size`, `--parallel`, `--flash-attn`, `--cache-type-k/v`, `--reasoning-effort`, `--reasoning-preserve`, `--jinja`, `--chat-template`, `--spec-type` (draft-mtp), `--spec-draft-model`, `--spec-draft-n-max` and the sampler flags.
  - The endpoints svalbard calls are present too: `/health`, `/v1/chat/completions`, `/v1/embeddings`, `/embedding` and `/v1/models`.
  - The archive layout is the same as b11840 apart from the dylib sonames, which went from 0.x to 1.x. No code hardcodes sonames.
  - v1.0.0 removes `--defrag-thold`, which svalbard never passes. Its new security opt-ins cover server-side tools and private media URLs, and svalbard uses neither.
  - **Not done:** a runtime test that serves a model and checks chat, embeddings and the MTP drafter. The sandbox blocked stripping quarantine to run downloaded binaries. Run that test before merging. If it fails, revert only `llama-server.yaml`.
- **Pi 1.6.0.** The breaking changes in 1.5.0 to 1.6.0 cover hosted-provider defaults, the extension API, and dropping `"tools": []` for OpenAI-compatible providers. Nothing changes in the custom-provider `models.json` that svalbard generates. I did not launch it against a local model. The binary grew from 114 to 131 MB uncompressed, hence size_gb 0.13.
- **Goose 1.60.** It removes chat mode (`GOOSE_MODE=chat`) and `goose review`. svalbard sets neither; it sets only GOOSE_PROVIDER, GOOSE_MODEL and GOOSE_CONTEXT_LIMIT, plus a stdio extension. I did not launch it.
- **go-sqlite3 v0.37 changed the database/sql default to `BEGIN IMMEDIATE`.** Every svalbard transaction writes (the searchdb inserts and reference_static), and drive-runtime opens databases read-only, so nothing is affected. The removed `FCNTL_NULL_IO` is unused.
- **angr on macos-x86_64 has no wheel.** That is true of both 10.0.5 and 10.0.7, so the bump did not cause it. With uv, all three Python pins resolve on linux-x86_64, linux-arm64 and macos-arm64. pwntools and sqlmap also resolve on macos-x86_64.

### Checksum pins

**How it is enforced (new).** `catalog.Item` had no `sha256` field, and `fetchAndRecord` called `downloader.Download(..., "", ...)`. So the `sha256:` already in framework-espidf and tool-esptoolpy was ignored when the YAML was decoded, and nothing was checked. The downloader itself has always supported an expected hash. The changes:
- `host-cli/internal/catalog/catalog.go`: new `SHA256` (`sha256:`, for `url`/`url_pattern`) and `PlatformSHA256` (`platform_sha256:`, keyed like `platforms`). These are artifact-integrity pins, separate from the Phase 7 acquisition hash.
- `host-cli/internal/apply/apply.go`: `fetchAndRecord` takes the expected hash. `downloadItem` passes `recipe.SHA256`, and `downloadPlatformItems` passes `recipe.PlatformSHA256[candidate]`. `Download` checks the hash after the download, deletes a file that does not match, and fails the job. A copy from `SVALBARD_CACHE_DIRS` that does not match is no longer accepted: it is downloaded again and checked.
- Tests: `TestApplyEnforcesPlatformSHA256` checks that a matching hash installs and a mismatch fails with nothing left on disk. `TestEmbeddedChecksumPinsAreWellFormed` checks that every pin is 64 lowercase hex characters and that each `platform_sha256` key has a matching `platforms` entry.
- The two PlatformIO pins are now enforced as well. Both match the checksums on the PlatformIO registry (`api.registry.platformio.org`).

**Pinned: 28 recipes, 106 hashes.** All come from the GitHub release API `digest` field, not from downloads. The 42 URLs also listed in `2026-11-21-pin-bumps-sha256.txt` all agree with it, and I checked one new asset (jq macos-arm64) against a local download.
